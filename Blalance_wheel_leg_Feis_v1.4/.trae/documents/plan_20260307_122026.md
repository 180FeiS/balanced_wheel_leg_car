# 恢复servo_control_table函数调用的实现计划

## 1. 问题分析
- 当前control.c中的left_leg_control和right_leg_control函数中移除了servo_control_table函数调用
- 这导致无法通过五连杆姿态解算逻辑来正确控制小车运动
- 需要恢复此关键函数调用，同时保留PWM参数控制功能

## 2. 实现步骤

### 2.1 恢复left_leg_control函数中的servo_control_table调用
- 在函数开始处添加servo_control_table(p, -angle, &pwm_ph1, &pwm_ph4);
- 保留PWM参数的边界检查
- 确保函数能够同时支持姿态解算和串口控制

### 2.2 恢复right_leg_control函数中的servo_control_table调用
- 同样在函数开始处添加servo_control_table(p, -angle, &pwm_ph1, &pwm_ph4);
- 保留PWM参数的边界检查
- 确保函数能够同时支持姿态解算和串口控制

### 2.3 确保PWM参数控制功能仍然有效
- 保持全局PWM参数变量的定义
- 确保vofa.c中的串口指令解析逻辑仍然能够修改这些参数
- 确保在调用servo_control_table后，如果通过串口修改了PWM参数，则使用修改后的值

### 2.4 验证功能恢复
- 确保五连杆姿态解算逻辑能够正常工作
- 确保串口控制PWM参数的功能仍然有效
- 确保返回值计算准确反映实际的舵机输出状态

## 3. 技术要点
- 恢复servo_control_table函数调用，确保五连杆姿态解算逻辑正常工作
- 保留PWM参数控制功能，确保串口指令能够修改PWM参数
- 保持边界检查的一致性，确保PWM值在合理范围内
- 确保返回值计算准确反映实际的舵机输出状态

## 4. 预期结果
- 五连杆姿态解算逻辑能够正常工作，通过ekf.c文件中的姿态解算来控制小车运动
- 串口控制PWM参数的功能仍然有效，能够通过指令修改PWM参数
- 系统能够正常运行，所有核心功能逻辑与原始版本保持一致
- 主函数中通过SendDataStreamToVOFA发送的舵机PWM值与实际输出一致
