# 解决舵机接口分配问题

## 问题分析
当前代码中存在舵机接口分配不合理的问题：
- 舵机1 (SERVO_1) 使用 pwm_ph4 接口
- 舵机2 (SERVO_2) 使用 pwm_ph1 接口
- 舵机3 (SERVO_3) 使用 pwm_ph4 接口
- 舵机4 (SERVO_4) 使用 pwm_ph1 接口

这导致多个舵机共享同一个ph接口，造成控制冲突。

## 解决方案
根据用户指示，重新分配舵机接口：
- 舵机1 (SERVO_1) → ph1 接口
- 舵机2 (SERVO_2) → ph2 接口
- 舵机3 (SERVO_3) → ph3 接口
- 舵机4 (SERVO_4) → ph4 接口

## 具体修改步骤

### 1. 更新 left_leg_control 函数
在 `control.c` 文件中：
- 修改 `left_leg_control` 函数，使用 `pwm_ph1` 控制 SERVO_1，`pwm_ph2` 控制 SERVO_2
- 保留 `servo_control_table` 调用，但调整参数传递
- 更新边界检查和PWM设置

### 2. 更新 right_leg_control 函数
在 `control.c` 文件中：
- 修改 `right_leg_control` 函数，使用 `pwm_ph3` 控制 SERVO_3，`pwm_ph4` 控制 SERVO_4
- 调整 `servo_control_table` 调用，使用正确的参数
- 更新边界检查和PWM设置

### 3. 保持串口控制功能
在 `vofa.c` 文件中：
- 保持现有的串口控制功能，确保 `p1+`/`p1-` 控制 pwm_ph1（舵机1），`p2+`/`p2-` 控制 pwm_ph2（舵机2），依此类推

### 4. 更新 main_cm7_0.c 文件
在 `main_cm7_0.c` 文件中：
- 更新舵机PWM输出值计算，确保每个舵机使用对应的ph接口变量

## 预期结果
- 每个舵机使用对应的ph接口：舵机1→ph1，舵机2→ph2，舵机3→ph3，舵机4→ph4
- 保持原有功能不变
- 串口控制功能能够正确控制每个舵机
